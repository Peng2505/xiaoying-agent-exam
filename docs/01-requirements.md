# 需求说明（第 2 题：内容任务规划 Agent）

## 1. 来源

- 官方题目：[`exam-question-2.md`](exam-question-2.md)
- 考试规则：[`exam-requirements.md`](exam-requirements.md)
- 项目规范：[`../AGENTS.md`](../AGENTS.md)

## 2. 业务目标

帮助运营人员在**预算**与**截止时间**内完成一份内容活动方案。

输入：活动主题、预算（整数模拟单位）、截止时间；合成素材库与费用/耗时表。

交付：任务计划、各步骤实际状态、工具结果、费用合计、已保存方案或明确未完成原因。

## 3. 功能需求

### 3.1 官方必须

| ID | 需求 | 说明 |
| --- | --- | --- |
| F1 | 真实决策循环 | 模型选动作 → 执行工具 → 观察 → 再决策或结束 |
| F2 | 四个业务工具 | 素材检索、脚本生成、成本估算、方案保存；结构化返回 |
| F3 | 动态重规划 | 超预算、工具失败、部分成功时可调整计划 |
| F4 | 硬约束 | 预算不超限；截止时间满足；缺关键约束不擅自补全；失败不标成功 |
| F5 | 保存前复核 | 保存前重新验证预算与时间 |
| F6 | 运行上限 | 步数或工具调用上限；达上限返回明确未完成 |
| F7 | 可复现证据 | 至少正常 / 信息不足 / 工具失败等真实运行记录 |

### 3.2 官方必须验收场景

- 正常完成
- 缺预算或截止时间
- 工具失败
- 预算超限
- 重复执行
- 无可行方案时返回未完成及缺口

### 3.3 官方加分 / 审核要点

- 失败步骤续跑并保留成功结果
- 合理重规划（非仅串行调用）
- 注入失败后观察调整

### 3.4 本项目自行增强（非官方硬性原文，但写入 AGENTS.md）

| ID | 增强项 | 目的 |
| --- | --- | --- |
| E1 | T07 `--resume` 续跑 | 加分项落地 |
| E2 | T08 决策步上限场景 | 明确上限证据 |
| E3 | 方案指纹幂等 | 重复提交不重复落盘 |
| E4 | `MAX_CUMULATIVE_STEPS` | 防止续跑反复新建步骤绕过单步重试上限 |
| E5 | 费用表全局最低成本证明 | T05 不可行不只依赖已观察估算 |

## 4. 硬性约束（确定性代码）

1. 缺预算/截止时间：CLI 拒绝，不调用 LLM  
2. 费用/工期：仅由 `data/costs.json` 计算  
3. 依赖未满足：守卫拒绝执行  
4. 已成功步骤：不可删除/改工具；参数变化不可静默复用旧产物  
5. 旧 `estimate_id` 不可用于新脚本保存  
6. `finish(completed)` 必须已有成功保存  

## 5. 成功标准（验收）

1. 真实 LLM 至少两条不同决策路径有 Trace（如 T01 vs T04）  
2. T01–T08 证据落盘且 `meta.json` 标明 `llm_mode`  
3. 单元测试可在无 Key 环境下通过  
4. 新环境按 README 可安装并运行 CLI / pytest  

未实际跑通的场景不得标为通过。
