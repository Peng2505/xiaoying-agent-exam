## 2. 关键技术取舍

1. **原生循环 vs 框架**：优先可解释与可控，避免框架掩盖决策边界  
2. **硬约束在代码、策略在模型**：费用不可由模型填写；重试/换方案由模型决定  
3. **断言不变量而非固定路径**：适应模型非确定性  
4. **续跑用状态摘要而非回放 messages**：避免 tool_call 配对错误  

## 3. 实际遇到的问题与处理

| 问题 | 处理 |
| --- | --- |
| Windows 管道中文乱码 | CLI 强制 UTF-8 输出 |
| 成功步骤复用未比对参数 | 业务参数比对 + ARGS_MISMATCH |
| 重规划误删成功步骤 | 守卫 PROTECT_SUCCEEDED |
| T04 duplicate 易误解 | 说明首次 vs 幂等复用，不改 Trace |
| 续跑新建步骤可能绕过单步上限 | `MAX_CUMULATIVE_STEPS` |
| T05 仅观察缺口不够 | 穷举费用表全局最低成本 |
| 独立审查：superseded 可复活、非法参数崩溃、指纹缺 outline | 最小守卫/校验/指纹修复 + 回归；T04 真实复跑不覆盖旧证据 |
| save 可用无关 estimate；finish 在有未完成步骤时仍可 completed | 依赖链产物校验；finish 校验当前有效必需步骤 |
| 默认 CLI 输出过长 JSON | 默认中文报告；`--output json` / `--verbose` |

## 4. 失败恢复方案（设计意图）

- 临时故障：结构化 `retryable` 错误 → 模型重试/换源  
- 超预算：观察 `within_budget=false` → update_plan → 新估算  
- 保存注入失败：incomplete 落盘 → `--resume` 复用成功产物  
- 达上限：incomplete + 原因码，不伪造成功  

## 5. 已知局限

- 素材与脚本为合成/模板，非生产 CMS  
- 模型路径不稳定；同输入不保证同 format  
- 全局不可行仅相对当前 `costs.json` 格式集合  
- 无并发调度、无鉴权、无前端  

## 6. 若继续开发

1. 为 format 增加显式「用户偏好」字段，降低 T04 触发偶然性  
2. 对「同工具新建步骤」增加每工具替换次数上限（在累计步之外）  
3. 将验收矩阵自动校验（CI 读取 meta/report 不变量）  
4. 补充更多素材匹配与截止时间不可行的专门场景
